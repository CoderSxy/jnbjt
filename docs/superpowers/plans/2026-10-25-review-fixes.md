# 平台审查问题修复 Implementation Plan

**Goal:** 修复本轮审查确认的七项问题，保留现有单体结构，不把演示数据当游戏事实。
**Spec:** `../specs/2026-10-24-jnbjt-platform-design.md`；范围为用户授权修复的审查问题。
**Architecture:** 继续 React/Fastify/Postgres。沿用当前工作区；修改可直接 review，不提交或部署。

## Tasks
- [x] 队列和草稿应用：先用并行数据库请求复现排队/幂等/认领竞态，用注入失败复现部分提交；事务 advisory lock 序列化队列，草稿行锁与城市版本更新同事务。
- [x] 截图链路：测试实际图片传输、模型 JSON 校验、取消及私有权限；接入排队识别，返回真实草稿或明确不可用；sharp 解码验证像素并去元数据，测试较大 JPEG。
- [x] 知识检索：真实导入后精确名称必须有正文，短词和跨城结果不能混城；按版本、名称、城市正确关联，去重后 limit。
- [x] 可靠生产：服务端从当前用户城市和 active 已核验配方构建计算输入；前端选择配方/目标/上线频率，助手只使用明确目标和城市，数据缺失时拒算；回归不同目标及无农田/草稿配方。
- [x] 编辑器：读取显式城市布局和加载版本，保存不重取版本；回归刷新重开、多标签冲突、城市选择；表单切换城市正确显示库存。
- [x] 浏览器验收：配置 Playwright 真正执行 .spec.ts，以隔离测试 API 和测试用户完成地图重开/409，以及生产缺失规则流程。
- [x] 全量 npm test、typecheck/build、test:e2e，独立复核差异，更新验收记录实测证据。

## Constraints / Review Focus
- 测试只用明确指定 jnbjt_test，不连接生产；并行测试用唯一用户避免相互 truncate。
- 未核验配方不能自动变为事实；未知库存/规则不能补 0，助手不默认 30 目标。
- 所有草稿必须人工确认；取消或失败不修改城市；跨用户不可读。
- 长任务执行并发 1、每用户活动任务上限 10；图片 10MiB / 2000万像素。
- 无真实模型、用户自有截图、生产环境时不声称完成实时准确率或生产验收。

## 实际结果（2026-10-25）

83 个单元/数据库测试、7 个 Playwright 浏览器测试通过；build 包括 Web 类型检查。浏览器使用受控 API，未运行真实模型或生产验收。独立复核新增的取消落盘、目标数字截断和队列 HTTP 状态问题已修复并复核通过。修改留在当前工作区，未提交、未部署；实际数据库迁移未执行。
