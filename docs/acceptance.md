# 验收记录

更新：2026-10-25，本轮平台审查修复。

## 实测通过

- `npm test`：21 个测试文件、83 个测试通过。数据库只使用 `TEST_DATABASE_URL` 指向的本机测试库；并发和生产规则新测试各用独立 schema。
- `npm run build`：API/共享包及 Web TypeScript 检查、Vite 构建通过。保留现有大于 500 kB 的前端 bundle 提示。
- `npm run test:e2e`：7 个真正的 Playwright 浏览器测试通过，使用本机 Chrome；前端浏览器测试用受控 API 响应，数据库契约由集成测试单独验证。
- 地图：选择指定城市、读取保存布局、刷新后导出一致；保存保留加载时版本，多标签冲突返回 409；手机可读取保存内容。首次保存并发冲突、原布局不存在但携带旧版本返回 409。
- 城市表单：选择存档显示实际库存，避免默认值误覆盖。
- 生产：服务端按当前用户存档、城市分支、active 知识版本及 reviewed/published 且有快照的配方计算；移除客户端演示规则。不同目标、库存、建筑数量、城市产出有明确断言；未审核配方、缺建筑、未知库存、条件表达式拒算。
- 助手：明确城市、目标总库存、上线频率才进入确定性计算；缺数据时说明缺失。拒绝把“1万”“10,000”或现有库存句中的数字截断成目标。
- 检索：精确名称返回正文；模糊检索按版本和城市关联，返回实际确认状态，去重后限流。
- 队列：并行入队幂等、10 个上限、全局并发 1 使用数据库锁验证；满队列对助手和截图入口返回 429。
- 图片：sharp 解码验证 JPEG/PNG/WebP，10 MiB / 2000 万像素限制，去元数据及重新编码；较大 JPEG 不再触发参数栈溢出。
- 识别：任务执行器读取私有图片、发送真实多模态请求、校验字段并形成可审核草稿。测试使用受控模型；无模型时明确标注未执行识别，字段未知。
- 草稿：同任务幂等；取消与草稿保存串行，取消删除待审核草稿；过期 worker 不落草稿，job 成功前不能应用；确认应用的城市与草稿更新同事务，失败整体回滚。非法库存校正被拒绝。
- 本轮独立代码复核通过；`git diff --check` 无格式错误。

## 启动 / 更新

安装依赖后运行 `npm run db:migrate`，包含新增 `006_recognition_jobs.sql`。本轮只对测试库执行迁移，未修改实际玩家数据库或部署生产。

生产配方需要人工审核为 reviewed/published；`import:bundle --publish` 仅发布知识版本，配方仍为 draft。本轮不把快照夹具或模型结果自行标记为已核验游戏事实。

## 未执行与适用范围

- 未连接真实模型进行 30 题实时评估，未用 20 张用户自有截图测识别准确率。
- Wiki 夹具仍为结构样本，未替换成许可允许的实时 HTML 样本。
- 浏览器测试使用受控 API，未宣称完成真实模型、完整运行栈和生产环境端到端 smoke。
- 助手计算目前支持一个粮食/银两目标，例如“苏州粮食到10000，每天上线4次”；有多个配方时需写明建筑与档位。不支持的数字格式会要求改写。
- 局部布局搜索是离线纯函数；异步 layout handler 仍返回离线使用提示，不宣称已交付在线布局优化。
- 未执行生产 ECS/Nginx 切换、公网验收、备份恢复、回滚或真实服务器内存测量。原计划各阶段的现场验收仍以实际执行记录为准。
